Set up a clean Slave PC

Use this guide after syncing the trading_backtest repository with GitHub Desktop. The commands create a local Python environment, install project packages, and start the Flask app.

Repository folder example
C:\Users\YOUR_USER\Desktop\Trading_Git\trading_backtest
1

Install Python once

Your PC already has Python 3.15.0. This guide is configured to use Python 3.15; first test whether all packages in this repository's requirements.txt support it. If installation fails because a package does not support Python 3.15, use a supported Python version instead.

Official Python for Windows downloads · If Python 3.15.0 is already installed, you do not need to install it again.

  • If installing Python, choose the Windows 64-bit installer and tick Add python.exe to PATH if shown.
  • Close and reopen PowerShell after installation.
  • Verify with py --version; expected output for this setup is Python 3.15.0.

Since your current PC reports Python 3.15.0, skip installing another version for now. If dependencies fail to install, save the complete error and then consider a compatible Python version.

2

Sync source code using GitHub Desktop

  • Install/open GitHub Desktop and sign in.
  • Clone the repository on a new PC, or open the existing local repository.
  • Choose the intended branch (usually main), then click Fetch origin and Pull origin.
  • Use Repository → Show in Explorer. Open PowerShell in that folder.

Do not overwrite local changes blindly. Commit/stash them first or resolve Git conflicts.

3

Copy and run these commands

Open PowerShell in the repository root first. Replace the example folder path with the actual folder on that PC. The commands below use the current folder automatically, so no username is hard-coded.

# Confirm you are in the repository root
Get-Location
if (!(Test-Path ".\app.py")) { throw "app.py not found. Open PowerShell in the trading_backtest repository root." }
if (!(Test-Path ".\requirements.txt")) { throw "requirements.txt not found in this folder." }

# Confirm Python 3.15.0 is available
$pyVersion = py --version 2>&1
if ($LASTEXITCODE -ne 0) { throw "Python launcher not found. Install/configure Python and reopen PowerShell." }
Write-Host "Detected $pyVersion"
if ($pyVersion -notmatch "Python 3\.15\.0") { Write-Warning "This guide is configured for Python 3.15.0, but detected: $pyVersion" }

# Create this PC's own virtual environment if it does not exist
if (!(Test-Path ".\.venv\Scripts\python.exe")) {
    py -m venv .venv
}
if (!(Test-Path ".\.venv\Scripts\python.exe")) { throw "Virtual environment creation failed." }

# Install/update required packages
.\.venv\Scripts\python.exe -m pip install --upgrade pip
if ($LASTEXITCODE -ne 0) { throw "pip upgrade failed." }
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
if ($LASTEXITCODE -ne 0) { throw "Dependency installation failed. Save the complete error message." }

# Start the main application
.\.venv\Scripts\python.exe app.py

Run the copied block in PowerShell. It will stop on a missing Python version or failed install rather than silently continuing.

4

Open the dashboard

When the terminal shows that Flask is running, open:

http://127.0.0.1:5000

Keep the PowerShell window open while using the app. Press Ctrl + C in that window to stop it.

Each slave PC runs its own local copy of the app and its own .venv. Updating code through GitHub does not require recreating the environment unless you change Python versions or the environment becomes broken.
5

When master PC code changes

  1. Master PC: save changes → review in GitHub Desktop → commit → Push origin.
  2. Each slave PC: stop the app with Ctrl + C → Fetch origin → Pull origin.
  3. If requirements.txt changed, run the dependency update command below.
  4. Restart app.py.
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
.\.venv\Scripts\python.exe app.py

Important: keep data and source code separate

  • .venv/: local-only; do not sync or commit it. Every PC has its own environment.
  • data/: contains project data/history in this application. Confirm which files Git tracks. Do not assume that data is shared just because code was pulled.
  • Multiple running PCs: avoid having several PCs commit changing SQLite databases or live trade-history files to the same Git branch. Database files can conflict or be overwritten. Keep a separate backup/export plan for each PC's records; share static historical candle files only when you intentionally manage them.
  • .env / API keys: configure separately on each PC and never commit secrets.
  • Git ignore: make sure .venv/, __pycache__/, secrets and machine-specific temporary files are ignored. Decide deliberately whether historical data should be version-controlled.
Important: This page is a setup guide, not an automatic installer. Python must be installed first. Review any error before rerunning commands, and do not delete the data/ folder to fix an installation issue.
